# 需求覆盖与后续开发

本表以平台需求的五个软件域及硬件域为线索，记录独立项目 **v0.1.0 工程验证版** 的实际覆盖。它是需求分解和接续开发依据，不能替代原始技术要求逐条签字验收。公开仓库只发布本项目独立实现和通用说明。

状态定义：**已实现**表示有本地实现及对应行为测试；**部分实现**表示只覆盖表内明确的子集；**适配待联调**表示已写协议适配，但没有外部真实服务证据；**未实现**表示本版本无此能力。界面静态检查不等于浏览器操作验收。实际证据见[验证记录](verification.md)。

## 接续开发顺序

1. 在目标机器完成浏览器、Windows/容器和真实Ollama联调，建立可追溯部署基线。
2. 加入企业身份/权限、审计留存、数据库/文件连接器、文档解析和向量索引。
3. 将执行器拆为隔离容器，接入GPU训练/推理、模型格式转换与质量门槛。
4. 开发标注、多模态数据工具、可视化工作流、技能/MCP和自主智能体运行时。
5. 接入集群算力调度与告警，按实际硬件、数据量和并发重新建立性能及故障验收矩阵。

以上是未完成需求，不是本版本已交付能力。原始平台全量开发尚未完成。
