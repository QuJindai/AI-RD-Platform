## 审查修复

- 限制数值输入、训练参数、指标和预测的非有限值；拒绝混合类型标签和超出合并列限的CSV/ZIP。
- 严格校验数据变换参数，非法字段或结构不再被静默忽略。
- 文本分块在达到5000条时立即拒绝继续保留切片，避免高重叠放大内存；检索先检查切片元数据总量。
- 数据转库、审批、工作流状态与审计使用同一SQLite事务；异常可回滚；任务仅在提交后入队。
- 工作流边端点先做类型检查，非法对象/数组返回客户端错误；快速审批不被原执行线程回写为等待。
- 安装成功后才写入依赖锁完成标记，安装中断可通过再次运行启动命令恢复。
- 身份/项目切换立即清空旧状态；按请求代次、身份和项目丢弃迟到响应；数据详情的成功和错误响应均校验当前选择，快速切换时清空旧预览。
- 任务变化与数据变换后刷新实际总览；过期或返回410的部署不再提供给预测；预览拒绝未知端点和断开图。

## 复现命令

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q --junitxml=test-results/junit.xml
node --check ard/static/app.js
node --test tests/test_ui.mjs
.venv/bin/python -m pip wheel --no-deps --wheel-dir dist .
```

另一个终端执行`bash scripts/start.sh`后：

```bash
.venv/bin/python scripts/smoke.py --base-url http://127.0.0.1:8000 --output test-results/http-smoke.json
```

令牌模式通过`ARD_TOKEN`与`ARD_REVIEW_TOKEN`提供两个不同用户身份；不要把实际令牌写入报告。脚本会创建明确命名的合成验收项目。

GitHub Actions工作流执行Python测试、JS语法及DOM行为回归、wheel构建和安装包真实HTTP验收，并上传JUnit/HTTP/服务日志。仓库中存在工作流文件不代表远端已成功运行；具体执行状态以固定提交对应的[Actions记录](https://github.com/QuJindai/AI-RD-Platform/actions)为准。

## 目标机器人工操作清单

1. 打开控制台，在桌面与手机宽度检查五个页签、侧栏、表单、空态和错误态。
2. 创建项目，主动生成合成样例；预览、清洗、拆分、合并、导出，核对来源版本仍保留。
3. 申请转库，换独立审核身份审批；训练分类模型并查看实际指标，部署、预测、停用。
4. 录入知识文本、检索并比对原文；保存含人工节点的流程，审核后确认同一任务继续。
5. 快速切换两个项目，确认迟到请求不覆盖当前页面；切换/清除令牌，确认旧身份数据全部清空。
6. 训练期间在表单输入文字，确认轮询不清空输入或跳动页面；总览随真实状态更新。
7. 检查过期部署不能再选用，核对资源、连接状态及审计链；正常重启后复核资产与等待审批任务。

当前交付是可运行的工程验证基线，完整原始平台开发和最终验收尚未完成。
